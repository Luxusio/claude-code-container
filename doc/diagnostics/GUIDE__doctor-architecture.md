# Doctor architecture

The synchronous public `runDoctor(projectPath): boolean` in `src/doctor.ts` composes the complete diagnostic application in `src/application/doctor.ts`. `src/ports/doctor.ts` requires semantic observations and publication capture; `src/domain/doctor.ts` describes the raw values without Node types. One OP-doctor owns the ordered checks, severity/message decisions, summary and returned boolean.

The application resolves the project, observes runtime readiness, and returns false after printing the runtime error when the daemon is absent. Otherwise it checks runtime version, image, container, identity-scoped mise cache, observed sessions, stale project locks and the launcher in that order. Warnings return true; errors return false. The actual CLI dynamically imports `./doctor.js`, calls the synchronous facade with cwd, and maps that boolean to exit 0 or 1.

The native facade retains project naming, runtime selection, identity resolution/cache naming, image/container helper semantics, session observation, lock directory lookup, fixed subprocess argv/options, the launcher report command and terminal sanitizer. It does not prune claims, acquire a diagnostic mutation lock, or repair anything. Main's existing home/profile prelude is separately owned.

Publication uses `capturePublication()` at every original log site. It selects the current native logger and original console receiver before the application evaluates the output argument. The returned closure publishes the computed string synchronously. A lazy sanitizer getter selects the native sanitizer before its message argument is read. Formatting, checks and aggregation stay inward; no native whole-report callback or buffered output is used. This preserves a throwing log getter preventing sanitation and a sanitizer replacing the logger without changing the already selected row logger.

Compatibility includes fresh runtime calls, two independent container-running observations, raw result identity/lazy getters, nullish version handling followed by falsy fallback, repeated launcher status/stdout/trim accesses, session length reads and uncaught failures. Native helper catches remain inside those helpers. Sanitation occurs once per printed message and replaces the existing terminal control/bidi characters centrally.

The missing-image hint still suggests the selected runtime's `build -t ccc .` in caller cwd. That existing hint may be unsuitable in a packaged installation outside a source checkout; correcting it requires separately authorized integration.

Verification separates frozen actual-source paired traces, inward behavior/type tests, native facade commands/publication tests, and source CLI branch binding from complete emitted declarations and actual shipped CLI resolution. The source CLI fixture executes the actual source-owned branch with a substituted module loader and exit effect; it does not execute main's prelude. Root owns full source-built dist and assembled/installed CLI acceptance, shared checker/inventory/WBS integration and final regression. Observation results and mock-only tests do not establish real native runtime/auth/platform reliability or whole Goal completion.
