# Remote host services and native authority

The complete host workflows for `remoteExec`, `remoteSetup`, `remoteCheck` and `remoteTerminate` are owned by `src/application/remote-services.ts`. Mutagen reuse/replacement/create and initial-sync polling are owned by `src/application/remote-sync.ts`. Domain contracts/validation/quoting/status parsing are in `src/domain/remote-services.ts`; required semantic effects are declared in `src/ports/remote-services.ts`. `src/remote.ts` retains every public callable/default and aliases the actual async workflow functions to avoid adding a Promise adoption turn. The CLI still dispatches these names from `src/index.ts`; no consumer, route or process owner moves.

The cohesive native adapter binds existing project/hash/profile/container-name helpers, config storage/legacy reader, SSH/Mutagen/tool/ping observations, local session claims/lifecycle locks, process signals, timer handles, console/progress/prompt and UTF-8/base64 encoding. Native results are returned intact and interpreted lazily by application policy. Inherited-stdio effects expose only their consumed error/status fields in the business type, without sanitizing the actual object. Output capture obtains the native console/stdout callee before message interpolation and invokes it with the original receiver. SSH reservation/refresh/release/stop accept a trusted shell-body thunk solely to preserve native callee -> user/host -> shell-builder evaluation order; no host workflow policy is hidden in that thunk.

Config chooses the current main `remote[projectHash]` object before legacy fallback. The legacy path is bound once only at fallback, with existence observation outside and read/JSON parsing inside the existing catch. Main settings failures propagate. Exec validates host/user, can prompt/save a supplied host, and reads current USER only there. Check preserves its read-only unvalidated display/reachability behavior. Setup only prints guidance. Terminate only observes/removes Mutagen sync and preserves success output even when the returned terminate result indicates failure. No installation, SSH auth/argv change or feature fix is introduced.

Exec retains the user@host/project remote prefix, captured expected container name, fresh token, 300-second lease and 30-second unref heartbeat. Local claim creation and signal registration remain before the try. Start/reservation is under the original async local lifecycle lock; project preparation, Mutagen endpoint and interactive exec use the exact captured container ID. Refresh and stop use the returned name/ID; release retains the pre-start expected name. Repeated name/profile observations are preserved, not cached into a new owner binding. Host forwarded-env selection/budget/order and fixed Claude program, shell quoting and base64 bytes remain unchanged.

SSH close/error registration and first Promise settlement remain explicit in application policy. Active-child signals are forwarded to that child before waiting/cleanup, then resent to self after cleanup; no-child signals clean first. Lease release marks inactive before cancellation/SSH. Release/claim/listener/callback failures retain their original precedence and can override later exit. Stop removes the local claim before the remote stop command; busy status42/output leaves the container and sync running, other failure throws, successful stop ignores returned Mutagen pause failure. Original duplicate local-removal behavior on failed stop/pause remains. This packet does not improve cleanup semantics.

`src/adapters/remote-shell.ts` retains the seven original native shell builders verbatim. Their private-directory owner/mode/no-link checks, descriptor-bound runtime identity, flock/shlock locks, wait/timeout, PID/token/final-token release and signal traps remain native authority. Reservation/refresh/stop marker and captured-name/ID fencing, live/expired/malformed peer handling, default-profile/legacy paths, remote image digest/native UID-GID cache scope and existing-container mount reuse remain exact. Native asset bytes alone are insufficient: the temporary-home fake-native branch audit must exercise replacement, identity, private roots, backend absence, timeout, peer disposition and final-token cleanup. No real SSH/Mutagen/Docker/Tailscale/network operation is needed for these tests.

Proof owners are the five `remote-services-core`, `remote-sync-core`, `remote-services-facade`, `remote-shell-parity` and `remote-services-type-contracts` files under `src/__tests__/architecture`, plus unchanged original remote/lifecycle/cache integration suites. Ignored task-local pre-edit actual-source imports and denied-native fixtures preserve all four workflow traces, shell strings, output/receivers, raw field priority and caught effect attempts. Author mock/syntax/source-byte results are nonattesting and do not replace independent code/security/QA, actual fake-native shell branch execution, complete compiler/build or both source-built and assembled/shipped CLI/declaration binding checks owned by root. Real remote SSH/auth/daemon/platform reliability remains a separate acceptance lane.

This is a source candidate for the complete four named operations. Helpers receive no extra credit; shared inventory/denominators and common guide updates are root-owned. Whole-operation acceptance requires every branch, public/caller binding, native authority audit and shipping proof. Source, portable, install, native and reliability evidence remain separate, and the full M00–M14 architecture Goal remains outstanding.
