# Clean architecture

The public named async `cleanContainers(options): Promise<void>` in [the native facade](../../src/clean.ts) projects results from [createClean](../../src/application/clean.ts). The application owns complete-inventory admission, managed-container filtering, image deduplication, selection, semantic progress, confirmation, locked cleanup and removal counts. It returns a finite `CleanOutcome`; the native facade constructs CLI errors and exits successfully after a completed cleanup. [Domain facts](../../src/domain/clean.ts) and [required ports](../../src/ports/clean.ts) have no Node imports or ambient native defaults; no port delegates the whole workflow.

The facade owns runtime selection, native command arguments and result decoding. It converts successful inventory into `{ kind: "observed", items }` and command failure into `{ kind: "unavailable" }`. Only this outer layer reads process error/status/stdout, splits native newline/tab output and interprets whether a container is running. Container facts carry `running`; their original status text remains available for display. Mutation ports return `{ ok: boolean }` rather than native process results. Native thrown errors propagate.

[The inventory failure requirement](REQ__clean-inventory-failure.md) defines admission and fixed error messages. Every inventory command checks error and status before decoding output. Failed output cannot become an empty or partial cleanup plan. This holds for both image repositories, optional volumes, dry-run and automatic confirmation. The application retains the hexadecimal ID/CCC-name checks, blank-image-ID rejection and first-ID deduplication across repositories.

Public fields remain only `volumes`, `all`, `dryRun`, and `yes`; CLI flags remain `--volumes`, `--all`, `--dry-run`, `--yes` and `-y`. Recorded all-projects/force wording grants no additional flag, label policy or claim bypass. Each operation captures one runtime authority before readiness and inventory. The captured runner, environment and working directory cover all inventories and mutations across confirmation; later ambient selection cannot redirect the observed IDs. A later operation captures independently.

Default mode excludes running containers. All mode stops each eligible running container before removing it. Every container uses the existing 180-second synchronous lifecycle guard and raw session-claim veto, including all mode. The application decides skip/stop/remove; native effects target captured IDs. Images and volumes retain their existing scope without an extra claim guard. Containers, images and volumes execute sequentially; the first mutation failure preserves earlier successful changes and aborts later work. No managed-label, lease, pruning or generation inspection is added.

Verification uses the existing [clean suite](../../src/__tests__/clean.test.ts) through the real facade with native fixtures, and the existing [strict contract](../../src/__tests__/architecture/clean-contracts.ts) against source and genuinely emitted declarations. Focused assertions cover inventory-failure admission, captured IDs, claim vetoes, running exclusion and stop-before-remove/failure order. The existing package checker and finite CLI cases in emitted, npm-extracted and Unix-installed payloads check delivery. These portable checks remain separate from native runtime/lock/claim acceptance, full integration and reliability; no native or whole-operation completion is implied by this guide.
