# Selected runtime capabilities and cache

The complete `getRuntimeInfo()` policy is owned by `src/application/runtime-capabilities.ts`, with facts/contracts in `src/domain/runtime-capabilities.ts` and `src/ports/runtime-capabilities.ts`. `src/container-runtime.ts` remains the public synchronous facade and owner of its process-local runtime override and cached object. Native observations are composed from `src/adapters/runtime-capabilities.ts` and the existing canonical runtime selector and Docker endpoint resolver. No endpoint selection authority, consumer binding or process owner moves.

The collector returns a cached object by identity before observing environment. A truthy raw `VITEST` flag with no explicit override publishes the original fixed Docker stub. Real collection preserves selection, version, Desktop, remote, rootless, flavor and socket order. The new semantic publication port returns `undefined`, rejecting asynchronous publishers in its TypeScript contract; the native assignment explicitly returns that value. It publishes only after the complete result exists; uncaught failures leave cache unpopulated and the next access retries. Environment changes do not invalidate a cache. Valid explicit overrides do; null/empty overrides are no-ops and invalid overrides fail before state mutation. Existing preload/reset hooks, returned mutable object identity and reentrant collection effects remain compatible.

Each native probe returns its original result object; status/stdout are read lazily by policy without normalization or destructuring. Platform is observed at each original branch, not once per collection. The raw WSL distribution port is evaluated only for Linux Docker without true Desktop capability, then its truthiness gates the mirrored `loopback0` observation. Non-Linux, Podman and Desktop paths skip it. UID observation preserves the callable test, second getter lookup and process receiver. Rootless fallback ignores UID faults; socket UID faults propagate.

Desktop capability requires original daemon identity and a local selected endpoint, or the exact native Windows Desktop Linux-engine pipe when identity is unavailable. Successful non-Desktop daemon identity defeats pipe evidence. `DOCKER_CONTEXT` remains raw and takes priority over trimmed `DOCKER_HOST`; a selected context is passed after `--` and failure does not fall back to host. Colima/native selected-context behavior and existing socket defaults are retained. The legacy `docker-desktop` flavor for remote Docker is presentation compatibility and does not imply `dockerDesktop: true` capability.

Public types/signatures and `runtimeCli`, `isContainerHostRemote`, `getHostInternalAlias`, `formatRuntimeSummary` remain compatible. Docker lifecycle/readiness/mount/capability consumers, container identity, setup, doctor, CLI commands and Codex/lab/session users keep importing this facade. SELinux/current-container mount caches and mount-argument policy are separate operations with unchanged reset behavior. This cutover introduces no TTL, frozen object, asynchronous probe, endpoint/socket fix, restart action or resource policy.

Proof owners are `runtime-capabilities-core.test.ts`, `runtime-capabilities-facade.test.ts` and `runtime-capabilities-type-contracts.ts` under `src/__tests__/architecture`, plus the existing runtime/selection/endpoint/setup/identity regression suites. Ignored task-local actual facade baseline/candidate witnesses preserve getter/callee ordering and faults with all runtime/daemon operations mocked. Those witnesses do not certify real Docker/Podman/Colima or macOS/Windows native acceptance. Root owns independent code/security/QA, compiler/default regressions and actual source-built plus assembled/shipped CLI module/declaration proofs. Until accepted integration, this is a whole-operation source candidate for `OP-runtime-capabilities`, with no helper, denominator or milestone completion credit. Full M00–M14 and separate source/portable/install/native/reliability acceptance remain outstanding.
