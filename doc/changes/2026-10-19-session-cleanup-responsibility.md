# Recoverable session cleanup responsibility

Session cleanup now preserves qualified responsibility when the CLI or its guardian exits, and the next admission recovers it before reserving another session. Current permission must authorize the exact captured container before device cleanup or stop; pending requests and unknown records retain protection. Shared-device and exact-container vetoes are independent, and retirement either completes cleanup or transfers responsibility to a qualified session. Known ceiling: if a native start happens before its positive callback is durably recorded, later running state cannot prove ownership; the startup intent remains incomplete. Legacy ambiguity and downgrade restrictions are documented in [the session responsibility requirement](../common/REQ__session-mutation-lock-lifetime.md#guardian-responsibility-and-orphan-recovery). Local fixture and emitted-process verification does not certify deployed macOS, Windows or provider behavior.
