# Container execution session cleanup

After ownership acquisition fulfills, container execution now attempts its existing session cleanup even when workspace-lock release, setup, clipboard or command preparation fails. It preserves pending-work settlement, captured-target shutdown permission, original failures and restore/dispose/cleanup ordering; defensive CLI cleanup remains safe to retry under existing policy. A later admitted native session starts a fresh cleanup lifetime without caller-side resets; successful cleanup or complete rollback removes its own signal registrations while failed cleanup retains interruption handling. The [requirement](../session/REQ__container-exec-owned-lifetime.md) records the separate retained-acquisition and runtime-authority limits, while the [architecture audit](../common/AUDIT__architecture-current-boundaries.md) distinguishes scoped verification from native or whole-Goal acceptance.
