# Fresh creation exposes semantic results

The creation application returns completed, refused or rejected facts and keeps
removal separate from independent absence proof. Native composition preserves the
existing CLI string/error behavior, captured runtime and inside-lock projection.
Native causes stay private; no new cleanup framework, retry or schema is added.
The shared mount-verification type is reused. See the
[derived creation contract](../runtime/REQ__container-create-outcomes.md).

Known ceiling: legacy unexpected-error formatting and unknown-created-ID
uncertainty remain. Portable source/emitted tests do not establish real native
Docker/Podman or Windows/macOS lifecycle acceptance. Full architecture acceptance
remains separate.
