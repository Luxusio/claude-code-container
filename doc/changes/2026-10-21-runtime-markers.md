# Runtime selection is independent of test-runner markers

CCC no longer fabricates Docker capabilities or skips nested-container bind translation because `VITEST` or `VITEST_*` is present. Runtime selection, captured native observations and mount translation follow the same policy in those environments; invalid configuration fails when selection is reached. Existing explicit overrides, caches and deliberate test preloads keep their precedence. The [captured runtime requirement](../runtime/REQ__captured-container-runtime.md) and [capability guide](../container/GUIDE__runtime-capabilities.md) describe the contract. Tests use explicit capability, invocation and host-context fixtures rather than an ambient production shortcut. Capture path resolution also consistently follows its explicit platform, including PATH separation and configuration/TLS references, while replay's private files use the real host filesystem. This correction adds no runtime provider, public API, storage change or testing framework; actual native platform acceptance remains separate from portable fixture checks.
