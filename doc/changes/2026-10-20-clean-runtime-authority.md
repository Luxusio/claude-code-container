# Keep cleanup on its captured runtime

Cleanup now captures one runtime invocation before readiness and inventory, then
uses that same executable and endpoint or Podman connection/store through
confirmation and deletion. Changing ambient runtime settings while the prompt is
open cannot redirect the observed IDs to another authority.

The reusable application returns typed completion or expected failure facts,
including completed-removal counts. The native CLI facade owns error messages
and its successful exit. Existing inventory admission, session-claim protection,
target IDs and removal ordering remain in place. See the
[cleanup contract](../cleanup/REQ__clean-inventory-failure.md).

Portable fixtures and emitted-code checks do not certify live engine deletion,
native locks, or Windows/macOS host behavior.
