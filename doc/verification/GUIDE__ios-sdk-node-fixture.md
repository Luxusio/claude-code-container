# Node iOS SDK fixture

`createFakeIosMcpContext` creates private home and tool directories and runs the real MCP SDK client and stdio server. Its generated `xcrun`, `appium`, `xcodebuild` and `appium-xcuitest-driver` programs use Node. The existing `node-provider-fixture.ts` preload routes command discovery and subprocess launches inside that MCP child; it does not install routing in the parent test process or fall back to real SDK tools. Direct fixture controls launch the tool with `process.execPath` and its script path.

The programs retain the effective original command outputs and marker order. Simulator list output keeps its original metadata order and unescaped created name. Shutdown/delete one-shot failures happen before state replacement. Screenshots contain `fakepng`; recordings contain `fakevideo`, with the original 800 ms natural-exit delay or 20 second normal delay in the returned Node process. The final original tool loop overwrote the `xcodebuild -version` implementation: the fixture therefore still logs that invocation and returns success with empty stdout.

Appium runs HTTP service code in the returned process, without a shell wrapper or a service grandchild. It publishes an authenticated pending allocation before asynchronous startup and records its native identity before binding. The allocation journal, marker and cleanup checks retain their token, file identity, PID, native start token, command hash, bounds and before-signal generation checks. Unknown or changed authority retains evidence and refuses cleanup; a marker's claimed command hash never supplies expected authority.

Expected Appium invocation authority comes from two fixed vectors: `node <owned appium script> server --port <port>` for direct lifetime controls, and that same vector plus `--base-path /` for the public provider. MCP transport authority uses `node <repository server.mjs>`. Linux and POSIX process observations hash their joined arguments. Windows uses the exact non-verbatim argument quoting of [libuv's Windows process launcher](https://github.com/libuv/libuv/blob/v1.x/src/win/process.c), including empty arguments, whitespace, embedded quotes and trailing backslashes. The observed native hash must match; no PID-only or normalized-hash fallback is accepted.

Fixture portability is verification support, not evidence of real Xcode, iOS hardware or Appium installation. A Linux command-discovery control for `where` does not establish Windows native execution. Actual Windows process identity, signals and filesystem privilege controls require an admitted Windows host; unavailable required controls remain unverified. Existing broad suites with other POSIX scripts retain their own platform limits. Source preparation and syntax checks do not establish runtime, shipping or architectural acceptance.
