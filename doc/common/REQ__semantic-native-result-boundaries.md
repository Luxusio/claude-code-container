# Semantic lifecycle and workspace results

Hyper-V lifecycle and Workspace repair applications consume semantic observations and explicit effects. Native process framing and Git metadata encoding belong to native adapters and outward presentation. The original [architecture contracts](SPEC__ccc-architecture-contracts.md) remain authoritative.

- Hyper-V execution success, valid resource observation and operation completion are separate facts. Create/start, stop/delete, provisioning, readiness and bootstrap applications must not inspect or fabricate native mode/provider/exit/output records. Native readiness and trace diagnostics remain opaque until outward rendering. Preserve captured receipt identity and bytes; apply semantic failure/deadline overlays without mutating receipts. A status-zero command with an invalid observation must retain its distinct refusal/diagnostic behavior.
- Ordinary Hyper-V stop still requires semantic success, exact VM identity and canonical `Off` before publishing stopped or clearing its journal. Preserve journal recovery, deadlines/reserves, locks, CAS, primary/compensation error precedence and partial-state reporting. See [stop completion proof](../device-lab/REQ__broker-stop-completion-proof.md).
- Both root Workspace registration recovery paths and nested/broken/addition applications consume already-classified Git completion, branch-head and metadata observations. Core retains admission, confirmation, branch/index agreement, ordering, revalidation and compensation. Native bindings decode command output and Git metadata and retain exact original bytes/identity privately.
- A Workspace metadata publication receipt identifies the actual inode and exact bytes installed by the native primitive, including validated no-op and recovery returns. A later same-byte successor must never become owned by recapture. Snapshot validation and no-op checks compare original bytes, not only decoded text or semantic equality. Restoration uses the exact receipt and refuses successor replacement.
- Preserve each existing operation's success predicate and diagnostic precedence at the native binding. Root/nested process-error handling differs from broken/addition status-only handling. Preserve native Git arguments, pinned environments, exclusive metadata publication and the post-index-initialization ownership refresh.

Runtime function names and package paths, public wire/error fields, persisted formats and existing side effects remain stable. Known inward factory/port/deep-declaration consumers migrate atomically to the semantic shapes. Old native-shaped object assignability is deliberately not promised; no parallel raw compatibility shim is required. Qualify actual emitted declarations and reached consumers, not only source aliases.

Verification covers semantic decisions with opaque receipts, both root recovery paths using owned temporary Git repositories, exact-byte/inode replacement refusal, branch/index mismatch, side-effecting failed addition and truthful rollback. Preserve actual native versus portable evidence and verify emitted callers and ordinary package consumers separately. Source shape/getter traces or tests of a verifier do not establish these behaviors. This boundary contract does not certify exhaustive external consumers, native Windows/macOS behavior or whole-Goal completion.
