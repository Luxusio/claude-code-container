# Semantic control and process boundaries

Control and observation applications consume semantic facts and preserve native evidence opaquely. Native adapters own command recipes, status/output decoding and public result materialization. The existing [architecture contracts](SPEC__ccc-architecture-contracts.md) and [semantic lifecycle boundary](REQ__semantic-native-result-boundaries.md) remain authoritative.

- Android control, orientation and transfer retain target/lease admission, validation, effect order, staging, conditional commit and `finally` disposal inward. Adapters classify this operation family's native success as `status === 0`, including receipts with error/signal fields; neighboring app-launch predicates remain separate. Domain navigation/orientation intentions do not contain ADB keycodes, rotation codes or native response fields. Preserve direct `keyCode ?? key`, including zero and arbitrary nonempty keys, native String conversion, defaults, whitespace encoding, emulator/physical navigation outputs and double-tap stream omission. First-effect failure prevents the dependent effect; transfer disposal and exception precedence remain unchanged.
- macOS provider selection, availability, instance and missing-reason policy stay inward. Native adapters construct Tart/VZ/UTM recipes and materialize the existing public provider plan. Preserve discovery/missing ordering, unavailable/null commands, SSH redaction and lazy empty/identity-only inventory. Public stored-softnet metadata remains distinct from actual Tart default-on softnet plus feature detection; false feature-cache entries, short-circuiting, headless behavior and existing budgets remain.
- Session domain/application own opaque owner tokens and active/stale/unknown policy. The existing native facade decodes Windows batch output and native process errors; it retains the public batch parser export. Preserve token comparison, qualified absence, uncertainty, batch fallback, Linux framing/zombie handling, canonical hidden Windows probes, trusted complete tasklist output and opaque ps birth tokens. Native POSIX success/EPERM is active, ESRCH stale and ordinary unavailable results unknown. Public native null/undefined probe throws retain their existing TypeError behavior; new semantic injected callbacks propagate their exceptions unchanged. Existing claim, guardian, lock and successor authority is unchanged.
- Public owner resolution accepts unknown input safely. Null, undefined, arrays and primitives return the existing semantic invalid-request outcome before identity, registration or auth effects. HTTP rendering returns 400 `invalid-project-owner-request`, `projectMountPath: ""`, `profile: null`. Existing malformed-field/profile diagnostics, registration agreement, 404/409/503 mappings and genuine unexpected 500 handling remain unchanged; the existing HTTP route and outcome renderer suffice.

Existing public runtime helper names, package paths, helper result shapes, wire results and persisted formats remain stable. Finite exact package exports may route the two legacy provider-domain helper modules to outward materializers while internal relative core imports remain pure. Preserve their other runtime exports too. Inward factory ports and deep type assignability deliberately migrate atomically to semantic contracts; the session domain's native batch-parser deep export is removed, with its existing facade export retained. Do not add inward native re-exports, parallel raw ports or a generic command framework.

Verification exercises semantic decisions with conflicting opaque receipt fields, actual native bindings/public presentation, failure and disposal ordering, token/uncertainty preservation and real private-loopback malformed-owner requests without auth writes. Actual Node and strict TypeScript package consumers must resolve the legacy helper export routes against genuine emitted/package artifacts, with `skipLibCheck: false`; Source aliases alone do not prove compatibility. Portable fixtures do not certify native Windows/macOS, exhaustive callers/exports, reliability or whole-Goal completion.
