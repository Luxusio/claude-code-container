# Codex launch preparation boundary

The domain owns the existing interactive invocation grammar. Application owns
the complete positive-absence probe, supported-command gate, profile refusal,
single daemon initialization, qualified no-daemon fallback and failure policy.
The public facade supplies five required native capabilities and retains the
original runner parameter/default, command encoding, probe script and timeouts.

Start argument binding occurs after positive absence and outside the help
catch. The original command snapshot is returned while recognition and native
argument construction observe the live inputs at their original points. Help
and fallback share the same probe options object; initialization spreads its
then-current properties into a fresh options object. Calls retain the bare
runner receiver. Raw result getters, signal/status mapping, string coercion and
catch-formatting failures are compatibility requirements, not normalization
opportunities. Constructing the application performs no native observation.

Verification uses the independent c284ead3 probe/source/declaration baseline,
core fault traces, actual inert native facade mutations, the unchanged Codex
launch and caller lifetime regressions, strict public/inward type consumers,
and both real emitted package forms. A private Node executable probe does not
prove daemon initialization in a real container or on another host platform.
Native acceptance and the wider M00–M14 conversion remain separate.

Current tool scope is Codex and Claude. OpenCode is excluded. Shared CLI,
shipping and migration accounting changes belong to the integration owner.
Hosted CI and pushes require explicit user authorization.
