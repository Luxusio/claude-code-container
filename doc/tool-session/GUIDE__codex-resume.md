# Codex automatic resume recovery boundary

The existing recovery requirements are in [REQ__codex-daemon-packages-volume.md](../common/REQ__codex-daemon-packages-volume.md#automatic-recovery-for-list_turns-resume-failures). This operation wraps eligible local interactive `codex resume` commands, recognizes one scoped native bootstrap failure, repairs that thread through native Codex, and retries the same UUID once. CCC does not edit SQLite or rollout history itself.

`src/domain/tool-session/codex-resume.ts` owns prompt-free command selection and the existing serialized plan shape. It preserves supported argument order and config overrides, removes picker selectors only from retry, and excludes prompts, images, remote modes and unsupported flags. Transport validation remains distinct from command eligibility: the recovery bundle accepts the existing nonempty string-array command/retry contract, including a custom executable supplied by an internal caller.

`src/application/tool-session/codex-resume-recovery.ts` owns original launch, failure admission, capability probing, scoped migration, optional metadata fallback, completion proof, one retry and final disposal. Required semantic ports bind those operations. The generic invocation values are opaque to the application; only native composition interprets the runner, effective home and reporter. The named four-argument async operation is exported directly from the compatibility facade so no additional Promise adoption changes completion or rejection timing.

`src/codex-resume-recovery-runtime.ts` composes the application with the existing native collaborators. `codex-resume-diagnostics.ts` retains exact final-error, UUID, canonical session-path and migration-result qualification. `codex-resume-metadata.ts` retains bounded native app-server initialization, canonical-home verification, targeted `thread/read` with `includeTurns:false`, returned rollout identity and clean-close verification. `codex-resume-process.ts` retains PTY quoting, native process execution, bounded capture, stdin framing, backpressure, signals, timeouts and listener disposal. Their authority is preserved through references, without copying native result observations or decoding them early.

Preserve evaluation boundaries when binding ports. Plan fields are read before the recovery `try`, so a throwing plan getter rejects without disposing a runner. A native callee is looked up before argument getters, command indexing, config/retry iteration and terminal-command construction. `runner.run` and `runner.dispose` keep the runner receiver, while reports are bare function calls. Interruption is read twice when truthy and once when false at the original stage boundaries; direct fallback and final retry have no additional check. Final disposal uses the latest runner method and can override another failure, as the existing `finally` does.

The command facade still reads `dist/codex-resume-runtime.cjs` only after selection and emits the existing rebuild/reinstall warning when that artifact cannot be loaded. Its fallback retains the copied invocation reference before serialization, even if a throwing serialization hook replaces the plan's command field. It now also imports `dist/domain/tool-session/codex-resume.js`; relocated artifact fixtures must include that dependency. The runtime bundle keeps the same entrypoint, Node target, CJS format, invocation JSON and sibling filename. No runtime transpiler is required.

Verification combines required-port core tests, consumed positive and negative type contracts, the canonical dependency scan across all five production roots, and the existing synthetic executable/metadata/package tests. Behavior tests cover failure qualification, bounded repair, interruption, raw faults, disposal and async completion. Existing native fixtures use temporary synthetic histories and executables. Portable and relocated-package evidence establishes this extraction's compatibility; actual user recovery is established only by a successful native resume in that user's environment.
