# Hyper-V monotonic operation budgets

The [architecture contract](../common/SPEC__ccc-architecture-contracts.md) requires operation-local monotonic budgets. The selected broker lifecycle, image, copy, network and canonical owner-cleanup paths use one local clock for each absolute deadline. Moving the host wall clock backward cannot increase their remaining allowance; moving it forward cannot prematurely expire that allowance. Existing suboperation caps retain their values; selected independent snapshot invocation defaults are specified below.

Existing exported helpers and setup entrypoints accepting absolute Unix deadlines keep that meaning when no local clock is supplied. Native elapsed-only sessions use a monotonic clock and accept an injected local clock for deterministic verification. Shared sessions receive relative durations and use their own local clock; a request cannot replace the shared session clock.

Network policy returns duration and termination reserve. Native adapters alone create Unix fields and native commands. No process-local absolute monotonic value crosses a worker, relay or PowerShell boundary. New elevation callers supply a finite integral remaining duration alongside the existing genuine Unix field; present invalid durations refuse, while omitted legacy durations capture their Unix remainder once. In duration mode the captured countdown governs expiry, including wall jumps between materialization and receipt.

Approval, consent, launch, authentication and bootstrap consume the original allowance. Each native receiver clamps a refreshed remaining duration to its existing countdown; transport must not grant a fresh full budget. Late acquisition cannot approve or dispatch a new operation after expiry. Keep existing executable, PID/start-token, nonce, administrator and terminal/close correlation checks.

Expiry prevents new dispatch and successful final publication. A previously delivered command may still have effects: preserve delivered-pending accounting, already-applied effect checkpoints, generation/CAS fences, journal evidence and exact compensation rules. Timeout does not prove cancellation, absence or permission to replay. Missing correlated child/relay termination proof retains the existing termination-unconfirmed result and precedence.

Readiness expiry preserves the last observed reason and partial scrub/media evidence, whether the refusal comes from native integral-budget admission or a core-local deadline check. An observed unsafe guest reason still requires the existing [readiness containment](REQ__hyper-v-typed-guest-readiness-containment.md) when the host provisioning ISO is absent. With no earlier observation, retain the existing first-attempt deadline classification and zero-attempt unavailable fallback. Verify native early-wake refusal, successive core clock reads, partial media cleanup and the public ISO-absent containment route in the existing readiness-adapter, create/start core and broker-command suites.

For shared mutation locks, a live Windows owner without a recorded process identity remains uncertain for both budgeted and unbudgeted callers. Wall ordering between process birth and claim publication cannot authorize reclamation. Preserve qualified exit, recognized reboot and recorded-identity mismatch recovery for both active and archived claims, with bounded asynchronous identity observations. Portable policy tests do not certify actual Windows process observations.

All shared owner-cleanup deadline producers and consumers use the same clock, including mixed-backend cleanup and canonical Hyper-V stop. Preserve the existing child-confirmation, relay-force and wrapper-completion shutdown ladder and its bounded total countdown. Audit/lease/journal ISO timestamps stay wall time; elapsed diagnostics use monotonic time.

Verification independently moves wall and local clocks during acquisition, queued execution, fallback, copy/hash, network publication and shutdown. It checks actual request allowances, effects, state and error precedence, plus existing legacy calls and genuine emitted consumers. Portable fixtures do not certify actual Windows/macOS or real-provider behavior.

General broker provider-worker startup/grace follows the selected contract below; detached provider startup/escalation remains a separate original obligation. Lifecycle-triggered snapshot-journal repair, independent snapshots and guest-direct actions follow their selected contracts. These contributions do not certify the entire Hyper-V graph, full source universe, reliability or whole migration.

## Broker provider worker and backend child allowance
Capture command, wrapper and completion ceilings before preparing or starting an executable worker. With existing command duration T, cleanup grace G and wrapper duration W (default T+G+15000), admission time t0 defines C=t0+T, Wd=t0+W, K=C+15000+G and parent fallback F=min(K,Wd+15000+G). The fixed15000ms overhead is captured once; failure does not renew it. Keep local ceilings monotonic and send only remaining durations to workers. Expired or cancelled admission cannot spawn a child. Worker startup, identity observation and command execution consume C; every native cleanup probe/termination consumes K or parent F. Post-signal grace is at most G and the remaining completion allowance. Default wrapper expiry grants no new cleanup reserve; a shorter explicit wrapper retains only its captured fallback reserve.

Synchronous and asynchronous parents share the same request/grant/cancel authority. Publish reduced positive integral durations before granting, permit only one admission and recheck cancellation at native spawn. The receiver subtracts its locally measured request-to-receive time from both reduced grants, conservatively preventing grant delivery from extending command or completion time without sending an absolute clock. Expiry refuses otherwise-successful final publication. Preserve genuine native rejection, spawn failure, output overflow, identity refusal and invalid transport as primary diagnoses; an elapsed timer cannot overwrite them. A bounded immutable private failure slot retains an already-observed failure during parent fallback; an exit potentially caused by cancellation is not fabricated as an independent rejection. Preserve explicit wrapper timeout wording and bounded output. Signal delivery, elapsed grace and Worker exit do not prove child-tree termination.

Cancellation atomically revokes dispatch that has not begun. Native dispatch already in flight must acknowledge its PID/identity publication or no-spawn result through the existing private admission state. Parent fallback resolves that handoff before taking its cleanup snapshot or terminating the Worker, within the same captured F. Synchronous waiting is bounded; asynchronous waiting keeps the parent event loop responsive. Expired allowance or missing identity retains truthful unconfirmed cleanup and never grants PID-only termination.

Optional remaining-duration inputs on selected native identity and Windows termination helpers consume one caller-owned countdown. Recompute before each subprocess, between Darwin probes and after successful observations, including injected identity readers. Present invalid or exhausted duration refuses without native dispatch or identity authority; omission retains existing helper defaults and positional APIs. Both Windows handle wait and its outer observation timeout fit the remainder. PID/start-token/hash and native handle checks remain mandatory; no timeout grants PID-only cleanup or replay.

Verification covers delayed startup, cancellation around admission, shared probe durations, independent wall changes, late success versus native failure, captured cleanup ceilings and existing real owned-descendant settlement in both runner forms and the direct backend child. Actual Windows/macOS and detached provider lifecycle remain separate acceptance obligations.

## Lifecycle recovery, direct transfer and legacy ownership

Every repair/status native primitive receives only positive integral remaining duration within the existing30000ms cap. Absolute local deadlines do not cross a process boundary. A repair without a parent captures one60000ms local monotonic allowance, covering repair/status together with their existing30000ms primitive caps. An explicit parent takes precedence and receives no fresh standalone allowance; composition, status, recording and remaining-time calculation use that same clock.

Check before dispatch, after successful completion, inside the repository lock immediately before publication after validation, and before journal removal. Deadline refusal retains journal/exact snapshot IDs/uncertain applied effects and cannot be classified as an ordinary repair failure that permits forced-delete supersession. Genuine native/validation/protocol failures retain their existing precedence. Restore a wrapped timeout-callback deadline only from the current invocation's own proven pre-dispatch refusal, never from a generic executor-failed code. Repair publication refuses missing or changed captured VM/generation/provider identity; unrelated current fields in the same generation survive. Conflict never clears the journal or patches a successor.

The [forced-delete supersession requirement](REQ__hyper-v-forced-delete-supersedes-snapshot-journal.md) applies to ordinary repair failures only while the parent budget remains and the captured VM/generation/provider identity and exact captured snapshot journal still match under the owner repository lock. These conditions qualify its earlier unconditional clearing/proceeding rule. Missing or replaced targets and changed journals return `hyper-v-snapshot-state-conflict`, preserve the current record and journal, and prevent deletion of a successor. Expiry retains the existing deadline outcome and journal. An unchanged target and journal with remaining time still permit ordinary forced-delete recovery.

Independent Hyper-V guest-direct actions use one captured monotonic allowance; mkdir and upload share it. Initial invalid values retain the existing typed-client1..300000safe-integer validation. Dynamic callbacks can shorten but never renew the allowance. Expired mkdir prevents upload, late success is refused, and genuine native/transport/protocol failures remain primary. Preserve one-shot credential isolation and no replay.

Wall publication ordering never proves replacement of a live identity-less Windows lock owner. Preserve uncertain live active/archive records for sync/async callers with or without an explicit budget. Existing proven exit, authoritative same-host reboot and recorded identity mismatch permit only existing token/fence-qualified recovery. Retain public publication-time codec/type compatibility while removing unused internal recovery authority.

Verification cues: owning snapshot/repository/public-broker tests exercise reduced native durations, parent expiry, locked publication, missing/successor refusal and force-delete journal retention, including failed repair followed by a missing/replaced VM or changed journal. Verify conflict409 and expiry504 preserve evidence without subsequent delete effects, while the unchanged-target ordinary failure still reaches deletion. Guest-direct fake-native requests prove fractional durations, independent wall jumps, no expired upload, initial validation and original failure precedence. Existing lock/identity suites exercise actual cold publication and independent contenders across active/archive, sync/async and budget modes, retaining positive recovery proofs.

Known ceiling: portable fake-native evidence does not establish actual Windows behavior. Existing100ms file-age grace and broader worker countdowns remain separate original-Goal obligations. Elapsed time never establishes effect absence or ownership authority.

## Independent snapshot invocation allowance

Initial journal repair, preflight, inventory retries, native mutation, confirmation, Linux SSH readiness and successful publication consume that same local monotonic allowance. The cleanup deadline is captured at the same admission: operation deadline plus the reserve below. Early cleanup may use unspent operation time and the reserve; catch/retry never creates another allowance.

Backend-less snapshot calls also allow this duration because the broker resolves the backend. Explicit caller timeouts and unrelated provider defaults retain their meaning. ## Detached provider native process allowance
The existing provider native process-identity adapter owns its command recipes and decoding. Every identity read, wait, refresh, observation, signal and termination captures a local monotonic countdown. Optional parent remaining durations can shorten it; each observed shrink is permanent and later growth or host wall-clock changes cannot renew it. Native timeouts are the positive integral minimum of the legacy cap and remaining duration. Invalid, nonfinite or sub-millisecond native allowance refuses dispatch rather than passing timeout0. Absolute monotonic values remain process-local.

Identity commands retain their5000ms caps and Windows taskkill its10000ms cap. Standalone identity/refresh/inspect/signal has a conservative10000ms total covering the two sequential ps probes; asynchronous independent probes remain parallel. Identity waiting uses its requested duration, with zero refusing all observation and no unrestricted final read. Existing termination timeoutMs remains a per-signal exit-observation cap, including Android3000ms and default1000ms; zero phase wait permits one immediate observation while the total remains positive, no sleep, then another identity-checked escalation. Ordinary termination captures3*(10000+phaseWaitMs); POSIX tree adds its initial10000ms identity observation and passes the same remainder through delegation; Windows tree captures10000(identity)+10000(taskkill)+phaseWaitMs. Envelope arithmetic saturates safely at the largest safe integer. These are captured ceilings, not renewed per-phase/native grants.

A successful match, same-birth refresh or exited liveness returned after expiry supplies no success, kill or cleanup authority. Expiry uses the existing unavailable/current:null/liveness:unknown or refusal result. A genuine returned mismatch/native failure retains its diagnosis; an admitted signal's ESRCH keeps its existing qualified race result. Recheck immediately before signal/taskkill. Preserve saved PID/birth/hash, every-escalation revalidation, birth-qualified Linux zombie proof, raw-PID forwarding to injected wait readers and one-argument injected reader/taskkill callbacks. Neither taskkill success, elapsed grace, missing identity nor delivered signal proves exit. Confirmation shares the original remainder and cannot start an unbounded final probe.

Verification covers local/wall jumps, irreversible parent shrink/growth, integral native caps, late observations and native failures, callback compatibility, unchanged per-phase waits, tree delegation and genuine exported/materialized consumers. A synchronous injected callback, native termination latency or overlong sleep cannot be forcibly preempted by the helper; the contract bounds native requests and late-result acceptance, not hard real-time completion.
