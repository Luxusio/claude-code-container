# QEMU image, disk and passive target operations

`createQemuImageDiskTargetApplication` owns image enumeration, disk materialization decisions and passive target selection. Its construction does not enumerate storage, discover commands or execute a provider. Pure domain functions infer supported image formats, bound command timeouts, build overlay arguments and project lab metadata into passive targets.

The Linux VM facade composes native leaves for owner context, metadata reads, canonical source/disk path validation, directory creation, provider status, the existing command runner, clock and lab publication. Existing ownership, symlink/ancestor and file guards remain in their original native functions. No port accepts a complete materialization or target workflow.

Image listing preserves native directory order, filters directories and omits unreadable or falsy metadata. A missing images directory returns an empty list without creating it. Disk materialization reads and validates the lab before inspecting the disk, rejects a running lab and reuses an existing disk unless `force === true`. Dry runs validate and plan without creating directories or publishing metadata. Real execution preserves the QEMU provider checks, runner lookup, environment identity, argv, cwd, timeout and raw command failure boundary. Successful execution precedes timestamping and lab publication. A later publication failure leaves the original partial overlay effect; there is no new rollback, journal or compare-and-swap policy.

Passive target listing selects one explicit lab when `labId !== undefined`, otherwise the owner's listed labs. Projection retains runtime and readiness metadata, stopped/running/failed classifications and guest/session hints. It performs no process, readiness, channel or guest probes. Other native callers reuse the same domain projection and format/timeout rules, including start and image-import paths.

The actual caller routes differ from the historical architecture inventory trace. Image listing is exported as `listImages`, reached through `handleLinuxVmManagementTool` and exposed by the public MCP `list_images` tool. Disk materialization and target listing are exported by the package and reached through `handleLinuxVmTool`. Public MCP deliberately omits `device_disk_materialize` and `device_target_list`; this extraction adds neither tool nor a broker exposure. Historical inventory remains evidence of its original classification, not proof of a public route.

The paired QEMU architecture core, facade and type tests cover immutable original behavior, native ordering and errors, strict synchronous ports and actual caller/catalog boundaries. Combined source/emitted declaration checks, genuine packed consumers, full portable QA and delivery remain separate acceptance gates. Source extraction alone establishes no native QEMU or whole-operation certification.
