# Host backend discovery

The broker host discovery route composes `createHostBackendDiscovery`. The inward application owns executable fallback order, backend availability and ordering, prerequisite and image-blocker decisions, complete output assembly, and the readiness timeout cap. Its request contains only owner ID, platform and command timeout; required ports expose executable lookup, host identity, Hyper-V readiness and the owner-specific Ubuntu image-cache observation.

The broker keeps executable authority, native PowerShell command construction and parsing, the existing output limit, and guarded private-root cache reads. Readiness runs only on Windows when PowerShell is available; Windows cache inspection still supplies image diagnostics when readiness is unavailable. Discovery does not start devices or acquire images.

The existing Linux image-readiness import path reexports the single pure implementation in `domain/broker-observation.ts`, so native callers and discovery share its blocker/advisory decisions. Existing owner/focused inventory, direct provider observations and public MCP routing remain separate peers. Completing this host packet alone does not complete the three public observation operations.

Ordinary broker and public routing regressions, consumed strict contracts and joint build/runtime QA are required before acceptance. Portable evidence does not certify real Windows, macOS, SDK or VM hosts.
