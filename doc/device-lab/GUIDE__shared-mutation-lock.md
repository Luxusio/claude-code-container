# Shared mutation locks

Each native facade composes one long-lived `createSharedMutationLock` instance. The application owns record admission, acquisition/reclaim decisions, contention deadlines, operation lifetime and release sequencing. Its finite ports expose namespace fences, exclusive claims, bounded raw records, clocks and pauses, process facts/identity observations, and token-qualified native moves. Native code retains paths, descriptor writes and closes, link/file identity, process observation, precise raw read outcomes, archive enumeration and qualified one-way movement/removal.

The two instances keep separate own-process retry state, observation caches, pending-observation deduplication and a four-slot FIFO queue. Identity observations cache ordinary results for one second and asynchronous unavailable results for thirty seconds; failed own-identity reads retry after one minute. Cache and pending admission are bounded at 128 keys. No application instance is recreated for each lock call or shared across the facades. One module-local registry spans their active claims using native-normalized file keys and retains each token when a displaced owner and a newer waiting candidate coexist. It detects synchronous self-contention across the facades and path aliases, but never authorizes file removal or reentrancy; independent asynchronous callers still serialize through the native file.

A complete valid claim uses authoritative same-host ownership evidence before considering file age. A proven exited PID, authoritative different boot or eligible verified recorded-identity mismatch may permit exact-token recovery even when the mtime is younger than 100 ms or lies in the future. Only malformed/null publication records use the existing age grace: retain them below 100 ms or with a future mtime, then apply the smaller of the stale allowance and one second. File age never authorizes reclaiming a valid live, identity-less, unknown or foreign owner. On the same host, a different boot identity, a proven exited process or a positively mismatched recorded process can permit reclaim. Live, unobservable and foreign-host owners are retained regardless of age. Native presence probes treat ESRCH and a well-formed Linux Z/X stat state as proven absence; failed or malformed stat reads remain conservative. Synchronous Windows observation avoids CIM; asynchronous recorded-identity uncertainty remains conservative. Budgeted asynchronous callers bound recorded-identity observations by their remaining allowance and refuse fresh queue admission when all observation slots are occupied. A late read-only observation grants no post-deadline mutation authority.

Normal container exec uses asynchronous lifecycle acquisition for initial start and readiness or tool-installation restarts. Await the start operation and propagate its final pinned ID through readiness helpers before using that ID. The distinct setup guard still spans preparation; runtime commands inside an acquired lifecycle guard remain synchronous. A positive own-process identity captured asynchronously is reused for later synchronous records in the same facade. Cold Windows synchronous publication may query CIM before exclusive creation when no external wait budget exists; an explicit wait budget avoids fresh identity queries and uses only a captured own identity. All callers retain live identity-less legacy records, including unbudgeted asynchronous Windows acquisition and archived owners. Process birth compared with a wall-clock publication timestamp cannot prove PID replacement because the clock may have moved before publication. Proven exit, authoritative same-host reboot and recorded-identity mismatch keep their existing token-qualified recovery authority. The publication-time codec and its exported type remain compatible for independent consumers; mutation-lock admission no longer depends on that codec or its one-second ordering. This does not change synchronous administration or exit callers into asynchronous APIs.

TypeScript synchronous calls retain `reclaimStale:false`. Both facades measure acquisition, own-identity retry and observation-cache lifetimes with monotonic time; persisted malformed-record mtime grace and ISO publication remain wall time. Positive ordinary acquisition and explicit parent allowances reject late admission and clamp pauses to the captured remainder; each observed parent shrink is permanent. Ordinary nonpositive wait preserves its immediate qualified-reclaim sequence without polling sleep, rather than promising a strict zero total-operation duration. Native entropy, owner host/boot facts and qualified release suffixes remain facade-specific.

Owned lifetime begins at exclusive creation, so complete-record publication, close and admission failures also attempt qualified release. Complete publication and descriptor close precede archive admission and final current-token verification. The application applies existing owner/age policy to this exact lock's displaced records. A live, foreign or unobservable archived owner blocks admission; qualified stale or safely malformed records can be removed. Native faults and hardlinked ordinary files remain unavailable and grant no malformed removal. An owned blocked candidate keeps its original wait allowance; a candidate that lost the main token removes only its own archives and retries within that allowance.

Native displacement moves main to a unique compatible archive and never restores it. A raced successor remains protected by its archived record. Release attempts the main token first, then this token's archives, with namespace rechecks and exact owner admission. Other tokens survive. Successful cleanup preserves the original error unchanged; multiple failures retain ordered AggregateError.errors with the original cause and primary string code. Positively observed owned cleanup failure reports shared-mutation-lock-release-failed. Synchronous self-contention and inherited exact-token asynchronous self-contention retain expired-budget timeout precedence. Partial malformed writes remain conservatively recoverable, and there is no pathname-only cleanup or new retry guarantee.

Ordinary shared-lock, crash-recovery and operation-lock tests exercise current files, stale/live process cases, budgets, successor preservation and failures. Required-port consumers accompany genuine package/root/architecture checks, build and shipping smoke. Static source review does not certify native hosts or complete the full storage/architecture goal.

For normal exec, order startup as setup serialization, immutable image preparation, asynchronous global Codex state acquisition, then asynchronous container lifecycle acquisition. Validate and hand off the exact runtime ID inside the mutation guards. After releasing them, acknowledge ownership and initialize the selected helpers under setup serialization. Keep the smaller helper set for safe deferred joins. Do not wait for the global guard while holding a container lifecycle guard, or move retained state mutation outside its global fence. Legacy startup compatibility must retain its own guarded entry.

Individual native lifecycle command timeouts bound the client process, not daemon effects or the entire setup. Failed or timed-out absence probes do not authorize compensation. Propagate cleanup failure instead of returning command success; when command/disposal/cleanup all fail retain all causes in execution order. Signal cleanup must normalize synchronous throws into the same controlled failure handling as Promise rejection. Linux zombie/dead stat states are positive exit observations; unknown reads remain protected.

## Successor correction qualification
Independent review1 found a vacancy between renaming a live successor and
restoring it. The current correction replaces restoration with one-way displaced
ownership evidence and post-publication admission. Both native facades and the
sync/async core are implemented; actual three-process regressions are in the
existing suites. This is the historical qualification checkpoint for that correction, not a live pending-work list. Subsequent regression/review/consumer records retain their exact revision and platform scope; this guide itself grants no global mutual-exclusion or WBS acceptance.

## Accepted correction contract and qualification scope
Existing unique displaced files become admission evidence. Moves are one-way
(main to unique archive to qualified removal), without link/copy restoration.
The application checks archived owner facts and the published current token
before entering. It retains a still-owned blocked candidate and the original
wait allowance; lost candidates remove only their own archives and retry.
Native enumeration matches only this lock's established suffixes, and native
reads/removal remain bounded, nofollow and namespace-fenced. Unknown read or
identity faults cannot authorize malformed deletion. Release attempts main
first, then this token's archives, preserving original failures and aggregation.
The actual three-process native interleaving is required before qualification.
Known ceiling: the exact live claim can reside in an archive rather than remain
at its canonical pathname — upgrade only if continuous canonical occupancy is
required through a true raced rename.
Known ceiling: legacy live/unknown archives block and old participants that
ignore archive admission are not qualified — upgrade when a separately scoped
mixed-version deployment or acknowledgement protocol is required.
