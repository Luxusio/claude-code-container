# Shared mutation locks

Each native facade composes one long-lived `createSharedMutationLock` instance. The application owns record admission, acquisition/reclaim decisions, contention deadlines, operation lifetime and release sequencing. Its finite ports expose namespace fences, exclusive claims, bounded raw records, clocks and pauses, process facts/identity observations, and token-qualified native moves. Native code retains paths, descriptor writes and closes, link/file identity, process observation and move/reread/non-overwriting restoration authority.

The two instances keep separate own-process retry state, observation caches, pending-observation deduplication and a four-slot FIFO queue. Identity observations cache ordinary results for one second and asynchronous unavailable results for thirty seconds; failed own-identity reads retry after one minute. Cache and pending admission are bounded at 128 keys. No application instance is recreated for each lock call or shared across the facades.

Locks younger than 100 ms are retained. Malformed records become eligible at the smaller of the stale allowance and one second. Different boot identity, an exited process or a positively mismatched recorded process can permit reclaim. Synchronous Windows observation avoids CIM; legacy or identity-unavailable live-PID locks retain the existing eight-hour fallback. Asynchronous recorded-identity uncertainty remains conservative. Bounded asynchronous callers use the synchronous observation route instead of starting fresh queued process probes.

TypeScript synchronous calls retain `reclaimStale:false` and use a monotonic contention clock with an external budget. Provider calls retain wall-clock contention and a separate monotonic external allowance. Missing external budgets retain their original timeout behavior. Native entropy, owner host/boot facts and qualified release suffixes remain facade-specific.

An admitted operation runs under the existing native namespace checks. Release rechecks that namespace, moves only the matching token, rereads the moved record and removes it only when qualified; a successor wins the original path. Restoration uses non-overwriting native link/copy attempts. Native fence or release errors can mask an operation failure, and an unsuccessful restoration can retain a moved record for diagnostics; the application adds no cleanup retry or stronger guarantee.

Ordinary shared-lock, crash-recovery and operation-lock tests exercise current files, stale/live process cases, budgets, successor preservation and failures. Required-port consumers accompany genuine package/root/architecture checks, build and shipping smoke. Static source review does not certify native hosts or complete the full storage/architecture goal.
