# iOS public wireless status

`createIosWirelessApplication` owns the public physical-iOS wireless action admission, read-only status selection and network visibility projection. Its two required synchronous observation ports reuse current discovery and xctrace inventory parsing. Native command execution, device decoding and response presenters remain in the adapter; status does not look up an attached record, claim a lease, allocate a session or pair a device.

This provider supports status only. Every other action is refused before discovery with Apple trust/Xcode pairing guidance. Missing xcrun and failed inventory retain their distinct diagnostics. A selected device determines network visibility by its connection marker; without a selected device, any visible Wi-Fi device makes network visibility true. A display name does not determine connection type.

Public MCP request policy and brokerApple trust diagnostics intentionally remain distinct APIs. The authenticated unattached default backend child reaches this same provider factory rather than forwarding to brokerApple. Ordinary core and existing public/native fixtures can establish those bindings; genuine macOS/Apple hardware trust and pairing remain separate native acceptance requirements.
