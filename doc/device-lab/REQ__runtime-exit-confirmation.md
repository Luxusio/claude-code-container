# Saved-incarnation runtime exit confirmation

Android provider termination and the synchronous QEMU stop adapter must confirm that the saved process incarnation has ended before clearing runtime metadata or authorizing dependent deletion. Full PID, birth and command identity remain mandatory immediately before every signal and escalation.

When QEMU reaches its existing post-signal exit-wait stage, use the bounded saved-incarnation observer. A changed displayed command after signaling is not proof of a live replacement or of exit. Native ended evidence may establish completion independently; unavailable observation, a live process or expired allowance must retain the refusal and recovery state. A failed non-ESRCH QEMU signal continues to refuse before that wait stage.

In the shared termination helper used by Android, if a native signal attempt failed after full identity admission, a separate positive saved-incarnation ended observation may qualify completion with `exited: true` and `signaled: false`. Retain the original native failure diagnostic. A failed signal alone, a diagnostic message, missing command identity or elapsed grace never establishes exit. Unavailable or late exit proof preserves the original failure and does not authorize another signal or cleanup. Successful-signal waits retain their existing liveness checks.

Reconciliation uses the original captured aggregate remainder and per-signal observation allowance. It adds no renewed timeout or unrestricted final probe. Existing injected observation contracts, zero-duration behavior and every-escalation identity checks remain required. QEMU retains its synchronous wait port and existing metadata/publication ordering.

Verify positive exit after an admitted signal failure, unavailable proof retaining the primary error, expired observations, changed live identity refusing further signals, and post-signal command changes with native ended versus live or unknown state. Actual macOS termination and provider smoke acceptance requires host results; portable injected observations do not certify the historical kernel state.
