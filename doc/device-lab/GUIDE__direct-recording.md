# Direct provider recording

`adapters/direct-recording.mjs#createDirectRecording` constructs actual finite native bindings and the shared application. Its result exposes `request(name, args)` for start/status/stop and `exited(deviceId, recording)` for guarded recorder exit observations. Native facades render semantic `success.value`, `failure.message`, `native.value`, or missing outcomes. Existing owner-operation and physical lease guards stay around the provider entrypoints. Public Android time-limit guards call domain `recordingInputError` before their native lock when the current selected-backend guard applies.

The application owns recording admission/defaults, semantic recorder selection, active/pending decisions, generation publication and compensation, finalization and artifact-retention policy. It reuses the accepted runtime-generation application/domain. Native mechanisms select owned devices and concrete executable/target facts, perform individual bounded commands and correlated helper requests, and retain filesystem/identity authority. The checked producer binds entropy/clocks, detached child spawn/events/startup observations, identity/signaling/PID waits and fenced stage effects; it imports no whole backend.

Android emulator rejects any existing recording on start. Physical Android resolves its selected ADB target and reconciles recording state first. Both retain their screenrecord arguments, 180-second default, remote pkill fallback, 300000ms pull/remove bounds and local-stage finalization. A refused local signal does not suppress the existing remote fallback. Only a signaled local process is waited for before claiming pending state. Failed transfer preserves pending recording; final CAS refusal preserves successor and remote artifact. Remote removal happens after a successful clear, and its thrown exception still propagates.

Simulator start rejects existing recording and records to a persistent `.recording-stage-` payload. Stop refuses an unsafe owned signal, then uses the exact generation's pending claim. Persistent-stage retry restores its fenced stage; legacy records populate a separate temporary stage. Failed population leaves the legacy source/pending metadata; failed commit or final CAS retains the persistent artifact, while disposable legacy stages follow the existing cleanup branches.

macOS start rejects existing recording and resolves its SSH bridge/workspace before spawning screencapture. Only macOS catches a thrown initial metadata publication: it suppresses its allocated recorder's exit publication, sends SIGINT and waits1000ms, then SIGKILL and waits1000ms if necessary. Other start variants retain their existing exception boundaries. macOS stop retains the remote pkill fallback, existing PID-based3000ms wait, staged SCP copy and remote removal after final generation clear.

Sandbox uses helper sessions rather than local recorder PID authority. Status and start reconciliation can publish a completed archive and conditionally clear its exact generation. Helper start/stop/status retain5000/10000/1000ms defaults. Short truthy limits select500ms capture intervals; other limits select1000ms. A failed start CAS stops the newly allocated helper session. Stop failures retain metadata for retry; a failed final CAS reports successor conflict only when a recording remains in the returned record. Archive path/correlation and bounded copy fences stay native.

All process exit callbacks call `exited`; identity match or unavailable observations preserve active state, while exited/mismatched observations conditionally publish pending state. Generation checks preserve same-ID successors. The application never claims universal rollback or verified local exit from a remote fallback.

Native composition uses the discriminated `DirectRecordingNative` contract. Common inputs are guarded find/update, default local path and output-path validation. Process variants add recording-directory and concrete target resolution; Android/macOS add individual command receipts, macOS adds workspace preparation. Sandbox adds individual helper request, verified archive path and bounded copy receipts. No complete start/finalize/reconcile callback or application-port bag is accepted.

Existing five-provider business journeys, macOS rollback/desktop-video suites and real authenticated default-child Sandbox/macOS journeys qualify the supported bindings. Small static contracts consume both actual factories; the strict architecture target checks real application and native producer bodies. Compiler/runtime/build/shipping and native-platform acceptance remain separate gates; this Guide grants no whole-operation or Goal certification.

Fixed ADB/simctl/SSH/SCP arguments and POSIX shell quoting live only in the checked native producer. The application invokes individual `spawnRecorder`, `fallbackStop`, `copyRecording`, and `removeRecording` effects with admitted target facts and semantic paths. It selects deadlines, defaults, effect order and generation transitions; each remote command leaf returns the concrete command receipt. The external native configuration and `runCommand(command)` contract are unchanged.
