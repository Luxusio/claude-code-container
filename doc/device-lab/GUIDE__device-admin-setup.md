# Device admin Hyper-V setup

`setupHyperVHost` composes the setup application; `devicesCliAsync` admits `devices setup hyper-v` through the setup domain and retains the explicit setup hook. The application owns diagnostic remedies, confirmation, result classification, license receipt decisions and presentation.

The facade keeps canonical PowerShell and plain-directory checks, directory creation, native command construction and execution, shared locking, and guarded receipt persistence. The confirmed application callback enables the feature and reconciles the existing typed host-fabric peer while holding the shared mutation lock. Diagnostic mode does not enable features, reconcile fabric or accept a license. Setup never reboots the host automatically. Receipt read/write failures retain their rejection behavior; failed fabric reconciliation does not publish license acceptance.

The required ports declare synchronous native leaves and the explicit asynchronous mutation lock and fabric peer. No legacy setup workflow is passed inward. Ordinary setup/network suites cover trust, lock budgets, fabric failure, receipt reuse/failure and manual reboot advice. Independent review and shared strict/build/runtime QA remain required; actual elevated Windows host setup is unrun on Linux.
