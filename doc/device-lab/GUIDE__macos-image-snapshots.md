# macOS images and snapshots

`createMacosImageSnapshots` owns base-image cloning and snapshot create/restore/delete policy. It receives finite native record, provider-plan, bounded command, recording, naming, clock and presentation leaves plus the existing inward lifecycle application. Base-image creation remains in that lifecycle peer. Claim/revalidation/replacement, Tart clone timeout compensation and successor-aware rollback are reused rather than copied.

Clone completes and releases the source lifecycle claim before publishing the destination. A source successor or publication conflict retains the current conditional-publication and clone-cleanup outcome. Native owner/source locks remain in the public facade.

Restore publishes a prepared candidate before deleting the primary instance. Matching prepared or activated recovery is resumed; activation failure preserves candidate metadata. Successful activation can still retain failed candidate-cleanup metadata and resources. These are existing partial effects, not an atomic operation or new rollback promise. Thrown native effects remain exceptions.

The domain owns eligibility, provider refusal, snapshot selection, recovery matching and the shared device definition. Native adapters retain actual Tart discovery/execution, process and resource identity, state CAS, guarded SSH/files and operation locks. Public results still use the current redacted device presentation. Portable ordinary tests and genuine emitted package checks verify wiring and policy; actual macOS/Tart acceptance remains separate.
