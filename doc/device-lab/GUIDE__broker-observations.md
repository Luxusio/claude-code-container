# Broker observation and preview boundaries

Broker observation applications live under `packages/device-lab/src/device-lab/application/broker-observation-*.ts`. They own owner-state iteration and caps, selected inventory queries, bounded lease enumeration and filtering, Appium metadata projections, broker/service fact sequencing, and lifecycle preview admission, conflicts, capacity and disclosure order. Their required ports are defined in `ports/broker-observation.ts`; passive requests and rules are in the two domain modules.

`device-lab-broker.ts` retains authenticated routing, wire validation and presentation, safe native storage readers, filesystem/path/process/date operations, native intent encoding, provider query execution and existing hosting/serialization guards. Inventory, list and broker/service observations add no resource lock, lease refresh, provider startup or state publication. Device status retains its existing physical admission and Hyper-V journal recovery effects. `broker.command.invoke` and focused Hyper-V `broker.device.tool.invoke` retain their existing outer serialization/operation authority, even when they delegate planning or inventory.

Owner inventory constructs each state-file grant and checks existence before the per-entry catch. Stat, byte rejection, safe reads, count caps and optional redaction remain inside that catch; redaction runs only on returned capped entries. Unredacted device objects keep their references. Focused inventory reads the owner snapshot before Android host/SDK observations and preserves missing versus undefined fields.

Lease scanning captures its directory before inspection, opens only after the existing native fences, counts every entry before filename filtering, accepts only canonical URI-encoded regular JSON names, and closes in `finally` before lease reads. Close failure can override an entry-cap result. Root/inspection failures and per-lease read/time failures retain their separate catch boundaries. Each owned lease reads its own current time; expired and foreign leases are omitted without pruning. Native date operations receive lazy producers so date-callee lookup precedes property reads. Shared TTL/expiry compatibility wrappers keep their argument/default timing for mutating callers.

Appium observations read metadata only. List projection reads ID, status and Appium fields for every object before filtering IDs; nullish defaults preserve false, zero and empty strings. Property errors remain outside the owner-read catch, and status retains the original device and Appium references.

Broker status reads service/runtime facts, address, hostname, two PID observations, paths, two independent root-presence observations, persistence, service projection/ownership and elevation in the original order. Service status normalizes options and owner before action refusal, observes plan/commands/dry-run/owner/installed facts before support/dry-run branching, and executes every synchronous query before classifying the first result. A failed query still yields a successful status observation with `running:false`.

Lifecycle preview keeps exact incarnation and physical-attachment fences, equivalent-create/missing-delete idempotency, metadata capacity checks, and native intent/query placement. Device and create redactors run before provider intent; their errors or mutations affect later queries exactly as before. Redacted Hyper-V plans skip native encoders. Existing iOS simulator plans can still perform the bounded native owner-identity query. The shared deterministic Android port selector is inward; native inventory/hash bindings and its compatibility wrapper preserve invoke callers without adding reservation or locking. Native command/definition encoders remain their existing lifecycle collaborators and are not a whole-lifecycle completion claim.

Device status consumes semantic lifecycle preview and direct Hyper-V operation/snapshot recovery outcomes. Finite native observation effects capture concrete connections and return explicit execution/protocol facts beside opaque diagnostic receipts. The application owns recovery, deadline, identity and projection decisions; the broker converter owns wire codes and redaction. Migrated status, recording and Appium constructors consume physical lease facts directly rather than interpret heartbeat HTTP responses. Other native consumers retain compatibility wrappers.

Verification uses ordinary consumed contracts, actual-source dependency checks and meaningful application/native fault fixtures. Existing authenticated RPC/MCP tests cover public mapping, recovery, authority and partial effects; synthetic tests of the dependency guard itself are unnecessary. Public declaration and emitted/packed/installer consumers are separate checks. Portable fixtures do not certify real Windows/macOS/Android/iOS querying, and broker facets alone do not certify direct/MCP operation closure.
