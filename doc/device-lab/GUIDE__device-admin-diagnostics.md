# Device admin diagnostics

`deviceLabSmoke`, `deviceLabBenchHealth`, `formatDevicesDoctor` and `formatDevicesSmoke` compose the diagnostics application. The synchronous CLI routes use the same application for prerequisite decisions, optional physical inventory, provider precedence, lease classification and aggregate outcomes. Inventory is an existing application peer. Public receipts, report text and terminal presentation belong to the existing admin facade.

The ports expose named probes and finite host facts alongside owner/device reads, guarded lease reads and clocks. Native bindings select executables, encode arguments and classify command output; opaque generic evidence passes through the application unchanged. Importing or constructing the application starts no provider. Real-provider smoke performs readiness and inventory commands without creating or claiming devices. A failed physical inventory is optional unless an explicit target is configured.

Ordinary probes execute before the installed MCP probe, while presentation places the installed row first. The native installed probe retains configured paths and existing distribution fallbacks and receives at least 15 seconds. Missing, failed and invalid observations remain distinct; failed inventory is never converted into proof of a missing device.

The current ordinary suites cover CLI admission, diagnostics outcomes and lease ownership. Independent review and shared strict/build/runtime QA are required before acceptance. Real Windows, macOS and physical-device certification remain separate from Linux test results.
