# Android command boundaries

Android applications request finite wireless, control and transfer capabilities.
Native adapters select ADB and construct its arguments; application ports carry
an opaque native target and semantic request data.

Wireless policy retains endpoint and IPv6 admission, defaults, optional follow-up
connection and the instruction to attach a visible device separately. Discovery
reports availability without exposing an executable to application policy.
Native command evidence masks the pairing code in arguments, stdout, stderr and
error messages before it reaches public diagnostics. Failed follow-up connection
also retains only the redacted pairing receipt.

Control policy retains navigation and orientation decisions, operation defaults,
two-tap sequencing and both rotation failure phases. Native leaves encode text
and build the ADB input/settings arguments. Transfer policy retains admitted paths,
owned staging, successful output publication and disposal; native leaves build
push/pull arguments. Neither capability bypasses the existing target or physical
lease checks.

Required synchronous ports are checked by ordinary consumed source contracts.
The wireless constructor no longer inspects function text, descriptors or getters.
Focused business tests and a compact authenticated default broker-child journey
replace the test fence's self-validation machinery. Existing public emulator and
physical-device suites qualify native binding behavior; private fake SDK results
do not certify actual ADB hardware.

This closes two demonstrated command seams and adds no WBS operation. Other
provider and broker result boundaries and final native acceptance remain separate.
