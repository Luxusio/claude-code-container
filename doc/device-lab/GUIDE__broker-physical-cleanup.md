# Broker physical devices and owner cleanup

`createBrokerPhysicalDevicesApplication` owns Android/iOS attach, detach, physical command stop and Apple trust decisions. `createBrokerOwnerCleanupApplication` owns owner-wide cleanup and the auxiliary-runtime cleanup used by other lifecycle applications. The broker binds required native capabilities and keeps authenticated RPC transport, owner/device/hardware locks, guarded state files, lease generations and trusted process termination outside these applications.

The applications return specialized semantic outcomes. The outward broker codec owns HTTP status, public response envelopes, command diagnostics, finite Android selection reason rendering and Apple trust/inventory presentation. Apple trust facts retain visibility, availability, network-visible connect disposition and the manual-required decision inward; provider labels, manual steps and attach instructions belong to the outward codec. A captured lease guard distinguishes exact, missing, identity-free and refused admission. A successful cleanup receipt also distinguishes an actual release from an accepted missing lease; only an actual release can authorize restoration using that guard.

Attach publishes an owner definition before starting its heartbeat. iOS and Android USB auto-selection observe visibility before claiming the exact hardware lease and nonce; an explicitly selected Android target is claimed before its subsequent inventory check. Android returned connection/inventory failures and publication failure branches attempt exact claim compensation. Raw native leaf exceptions retain their propagation, and a compensation attempt does not prove release succeeded. iOS attachment observes xctrace and does not pair or connect secretly. Only an exact detached ID/hardware match can be reattached; guarded publication repeats conflict selection under the native inventory lock.

Detach preflights the lease under its hardware lock, cleans owned auxiliary runtime, releases the lease and removes the definition by ID. A publication exception restores the exact released lease when restoration is available. Missing leases and partial failures retain their current diagnostics.

Broker physical `device_stop` is a hardware no-op. It cleans owned auxiliary runtime, releases its lease and publishes `status: "detached"` with cleared claim fields while retaining the definition. Direct Android/iOS provider stop remains a separate peer with its existing attachment/lease behavior. Auxiliary cleanup advances the expected record only when its publication commits. An ordinary successor conflict is reported without overwriting or restoring against the successor; a genuine write exception after release attempts exact lease restoration.

The physical stop application receives the selected device and expected generation. Its native composition retains the public command plan. A required physical stop observation still invokes the native runner for the no-op, so a returned runner failure prevents release and publication. Android connection and physical stop return only `{ok,receipt}` inward. The existing native normalizer owns `status === 0 && !error`; the application uses `ok` and carries the opaque receipt to outward presentation. Apple inventory is one semantic observation: observed devices (including an empty successful inventory) or a failure with missing-executable/command-failed reason and an opaque native receipt. The native binding decodes xctrace only after status zero with no error; executable and argument recipes stay outside the application.

Owner cleanup retains default stop/detach options and backend aliases. It rereads each device under its operation lock, runs native effects outside the short inventory mutation lock, and conditionally publishes against the observed record. Partial clears and backend failures are accumulated rather than hidden. Recording cleanup does not pull, copy or delete recording artifacts. Appium process identity and Windows watchdog authorities remain native.

Running virtual devices use the existing canonical stop operation under the already-held device lock. The shared native callback retains provider confirmation, Hyper-V host locks and journals, Sandbox singleton release, and conditional publication. Owner cleanup neither invokes a separate raw stop command nor republishes its predecessor. The semantic stop result carries actual committed auxiliary progress separately from its opaque execution receipt. Required refusal counts as failure; the aggregate report keeps its existing HTTP envelope.

Auxiliary process ports distinguish accepted signals from observed exit. The synchronous native observer checks the expected process birth, including Linux zombies and replaced PIDs, within one monotonic budget. Alive or unknown observations preserve metadata and block physical lease release. Appium retains verified TERM and authorized KILL; recording uses INT without forced termination. Exact predecessor checks run between auxiliary effects and before escalation or publication. The physical hardware guard remains synchronous throughout. Watchdog cancellation proves its cancellation marker was published, not that a process exited. See [stop completion requirements](REQ__broker-stop-completion-proof.md) for deadlines and refusal behavior.

Public bindings remain `broker.physical.attach`, `broker.physical.detach`, physical command plan/invoke, `broker.apple.trust` and `broker.cleanup.owner`, including exported physical/Apple callers and broker-supervision shutdown cleanup. MCP attach/detach and command routing keep their existing paths; no Apple MCP tool is introduced. Administrative cleanup remains a distinct peer.

Ordinary fake-port tests cover application decisions, while existing authenticated public/native fixtures cover the broker bindings. Consumed contracts check required capabilities and semantic results. Real Apple/Android hardware certification requires an actual host run and is not implied by these tests.
