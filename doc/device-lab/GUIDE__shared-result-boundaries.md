# Shared Device Lab result boundaries

Shared applications decide what happened before native composition renders the
public response. Native command exit codes remain observations; broker HTTP
status and MCP content belong to the outer converter.

The macOS lifecycle exposes clone failure evidence containing the target,
command receipt and optional timeout-cleanup receipt. Snapshot recovery retains
its guarded candidate publication before asking the native presenter to describe
the failure. Generic presentation results remain opaque to the application.

The screenshot reader returns image, missing or invalid facts. Mac and X11
applications consume those facts, while their native converters produce the
existing PNG/error response. The compatible `screenshotFileResult` converter
remains available to other native callers. Descriptor, link and size checks stay
in the reader. Remote cleanup still precedes local stage disposal; an exception
in remote cleanup retains its existing precedence.

The iOS native response type lives alongside native response helpers. Moving its
declaration does not change iOS workflow behavior or public payloads.

Hyper-V desktop applications return success or failure facts. Failures distinguish
invalid input, access denial, a missing target, conflict, an oversized result,
guest command failure, an unsupported capability, provider failure and an
unavailable dependency. The native broker maps these to the existing HTTP status
and MCP response. Recursive window, focus, type and scroll operations inspect
semantic success. Screenshot geometry is published before native image rendering.
Actual guest and native process exit codes retain their original meanings.

These changes add no operation to the WBS. They address four confirmed result
seams; they do not certify every remaining application boundary, native platform
or reliability requirement. Ordinary source contracts and business regressions
qualify the implementations without per-feature runtime compiler engines.
