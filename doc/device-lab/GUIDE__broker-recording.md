# Broker recording

Authenticated `broker.device.tool.invoke` routes recording start, stop, and status through one broker recording application. The application owns support decisions, runtime metadata, publication conflicts and finalization. It returns semantic observations, started/stopped facts, refusals and partial effects; the native broker converter supplies the existing public responses. Required native leaves separately launch Android/iOS recording, stop Android recording, pull its artifact and remove its remote file. Process recipes, private output paths, process identity, signaling and atomic state mutation remain native. Device operation locks remain in the broker binding.

Broker-managed recording uses Android screenrecord or an owned iOS simulator. Android defaults to 180 seconds. Windows Sandbox and macOS recording continue through their existing backend guest-helper routes; physical iOS recording remains unsupported through this broker path. Recording does not start a device or create an Appium session.

Status does not execute a provider command. It retains recording metadata when process identity is current or unavailable. A verified exited or mismatched Android recorder with owned remote media becomes a stopped pending recovery record. Status preserves pending and copy-complete records. Every recording publication atomically compares the captured target inside the owner-state lock: device ID, backend, incarnation and creation identity, Android serial/port or iOS simulator identity, and physical attachment claim. Mutable status and heartbeat fields do not invalidate that comparison. It also compares captured runtime identity, paths, active/stopped state and artifact receipts, so delayed status cannot erase newer recovery state even when the runtime ID is unchanged.

Start validates the supported target and physical lease before launching. It refuses `recording-artifact-copy-pending` while stopped Android media still needs recovery or removal. Successful launch records the actual PID and identity. If publication loses a generation race, compensation signals only that newly launched unpublished runtime through the existing process identity guard and reports the actual rollback outcome.

Stop preserves active metadata when signaling fails or exit remains uncertain. A validated identity mismatch or exit skips signaling and remote process-name stopping; malformed or unavailable expected identity authorizes no signal or media effect. An already-stopped recovery record retries finalization without stopping another recorder. A process-name `pkill` result is never evidence of exact remote PID ownership or verified host exit. If remote `pkill` fails after the owned host recorder was successfully signaled, confirmed host exit still permits artifact recovery. Recording, identity and physical lease guard refusals always stop further effects.

After verified recorder exit, stop conditionally publishes `active: false` and `artifactCopyPending: true` before copying. A publication error or conflict prevents the copy. A failed copy reports `recording-artifact-copy-failed`, keeps the remote source and pending record, and allows another stop to retry. Successful copy is followed by conditional publication of `artifactCopied: true` before removal. Failed copy-complete publication preserves the source; failed removal preserves the copy-complete receipt. A later stop skips copying for that exact receipt and retries removal using its recorded destination. State clears only after successful guarded removal and a matching final publication. A failed final publication retains recovery evidence. Both auxiliary cleanup and owner device cleanup preserve incomplete Android media recovery; signaling an active Android recorder alone cannot clear its artifact metadata. Default physical cleanup also retains the exact Android attachment lease and attached state while pending, copy-complete or active owned media still needs recovery. Cleanup reports the retained recording as a failure; a later recording stop can recover it through the same attachment. Recovery flags are optional and stopped legacy receipts remain protected.

Native Android stop, pull and removal receive a captured `BrokerRecordingArtifactContext` containing owner, target and recording. Each synchronous effect independently checks the exact recording state, process identity metadata, device incarnation when present, provider serial and physical attachment claim. Stop's host signal supplies the same optional context. The device-operation lock remains outermost; a physical lease lock surrounds each native effect and its short owner-state check. No lease lock is held while waiting for exit. Successor recording generations, replacement device incarnations and foreign or replaced physical leases refuse effects.

Ordinary application and consumed type tests cover policy failures; existing authenticated command, process, file, and lease fixtures cover native bindings. Real ADB and iOS recording require an available host and device. Static author checks are not runtime acceptance; independent review and coordinated QA precede delivery.
