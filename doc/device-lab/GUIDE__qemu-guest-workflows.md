# QEMU guest access and owned data

`linux-vm.mjs` binds trusted owner state and guarded native effects to two applications. The exported helpers and the locked `handleLinuxVmTool` route use these same bindings. Hyper-V broker snapshot dispatch remains unsupported.

`createQemuGuestAccessApplication` owns session admission, channel selection, public projections, readiness aggregation and guest-agent status history. Its required synchronous ports observe process existence, report SSH availability, execute an accepted guest command, optionally provide an explicitly selected readiness observation, read and write the owner lab, and supply the clock. Native composition owns SSH executable selection and argv. Process existence is not birth-identity proof. Failed readiness and agent observations still publish their existing bounded histories. Native process and SSH mechanics stay in the provider. A configured SSH session is available without being verified; no raw shell or monitor socket is exposed. Process-only readiness stays `process-running`. Status and readiness do not provision the agent; provisioning and start reuse the accepted lifecycle application. Session, readiness and agent-status histories retain the latest fifty entries.

`createQemuOwnedDataApplication` owns sync/export root eligibility, bounded copy policy, operation history and snapshot state decisions. Canonical path facts, symlink and secret scanning, copy execution, disk validation, qemu-img discovery/argv/execution and guarded lab writes remain native. The application uses synchronous `qemuImgAvailable` and `executeSnapshot` with the action, name, admitted disk, lab and budget. Execution rediscovery may fail after availability; that failure preserves snapshot metadata rather than publishing success. It reuses the guest-transfer normalization and history functions. A failed command cannot publish successful snapshot metadata. Listing is allowed while running; mutations require a stopped lab. Missing disks or qemu-img retain metadata-only success, and only restore changes `activeSnapshot`.

Publication remains the current raw `writeLab` operation under the existing public operation lock. No compare-and-swap, stronger atomicity, or rollback is introduced. A copy followed by a publication exception can leave copied files; that partial outcome is preserved. The export default name keeps its native clock behavior. Native file identity, ownership and secret protections remain authoritative.

Ordinary core and consumed type tests exercise these decisions with finite ports; existing provider and MCP tests exercise native files, failure outcomes and the public routes. Strict compilation, genuine packaging and runtime acceptance are performed by the task's independent QA actor. Source inspection alone does not certify a live QEMU guest, SSH endpoint or guest agent.
