# Bounded Device Lab state-file access

The generic state-file facades now compose bounded content read and JSON validation through `providers/application/state-file-read.mjs` and the explicit `providers/ports/state-file` contract. The application sees opaque content and required read, decode, parse, validate, error recognition and invalid-state construction ports. It imports no filesystem, path, Buffer, descriptor or Node Stats mechanism. Construction has no owner/home/root defaults. Existing callers pass their current trusted filenames and roots per call; this seam introduces no wire-visible path or adapter authority.

The parser port accepts a decode thunk. The facade expression `JSON.parse(decode())` evaluates the parser getter before invoking the decoder and retains JSON as its receiver. UTF-8 decoding retains bytes as its receiver; validation is invoked as a bare call. Missing content returns before all three. Native byte read occurs outside JSON classification. Decode, parse and validator faults retain the existing invalid-state error conversion and existing error identity.

The TypeScript facade retains its additional outer classification catch. The shared provider facade retains its two inner catches without that outer wrapper. Stateful or throwing `Symbol.hasInstance` recognition and failing error constructors can observe this distinction. Each facade reexports its own native adapter's error constructor; the TS and shared constructors remain distinct. Legacy error names, codes, causes and TS instanceof-only recognition remain unchanged.

Dedicated native adapters are `src/device-lab/adapters/state/state-file.ts` and `providers/adapters/state/state-file.mjs`. They cohesively own open/read/stat/close and root fences. The public descriptor callback remains an explicitly native compatibility API with descriptor numbers and Node Stats. It is not a business port. Read fences preserve ordinary files, single links, conditional nonzero dev/ino proof, stat and actual max+1 byte bounds, no-follow flags, error wrapping before callbacks, raw callback faults and finally-close precedence. Root-fenced TS reads recheck root and open-file identity before and after reading.

The TS in-place binary writer retains the original mechanism: existing files open without truncation, missing files create exclusively with mode 0600, root and identity prove safe before truncation, partial writes finish in a loop, and final size/identity/root checks precede close. Nested-create rules remain unchanged. This writer does not promise atomic publication, fsync durability or a new write-size ceiling. The shared generic facade does not gain TS-only writer, fenced-reader or error-recognizer exports.

Both owner readers now compose `providers/application/owner-state-content.mjs` through its finite `providers/ports/owner-state-content` contract. The shared application reuses the existing pure owner payload validator. It parses bounded text, admits device identities and checks the UTF-8 byte size of the pretty-serialized replacement envelope. Required native leaves supply the ID pattern, byte length and each facade's own state-error construction and recognition; the read method accepts a synchronous bounded-content leaf.

Bounded reading remains inside the read/JSON error catch, while payload validation runs after that catch. Known native state errors pass through; JSON syntax and raw content-read failures become the facade's invalid-state error with their cause. Writable admission validates before serialization, accepts equality at the byte limit and leaves serialization faults raw. The application opens no file, publishes no state and owns no lock. `src/device-lab-owner-state.ts` keeps its captured parent-directory fences and final recheck; `providers/state/owner-device-state.mjs` keeps its different native reader. Both retain open-file/link/identity checks, max+1 reading, outer errors and finally-close behavior. Shared owner repository, broker registration/resolution and mutation policy remain separate.

Atomic replacement and streamed copy now compose `providers/application/state-file-publication.mjs`. Required native ports capture and recheck namespaces, derive private stages, observe temporary files and writer liveness, open guarded source/output resources, read/write bounded chunks, perform one rename attempt, set permissions and remove stages. The application owns eligible temporary names and age, transient rename retries, stage/publication order, JSON serialization, accumulated byte limits and partial-write progress. Descriptors and buffers stay inside native resource scopes. Zero-progress writes fail without publishing the stage.

The TypeScript and provider adapters retain different fences and cleanup precedence. Provider publication rechecks the captured parent namespace around rename and stage removal; TypeScript publication retains its existing outer rechecks and best-effort destination permissions. Copy closes an opened output before stage removal. A native close, fence or removal error can mask an earlier error or prevent later cleanup; this extraction does not add an unconditional rescue or durability guarantee. Token-qualified lock moves use the same bounded rename policy through their existing native checks.

The shared mutation-lock application owns acquisition, stale admission and operation lifetime, with native identity and namespace authority described in `GUIDE__shared-mutation-lock.md`. These source changes remain a partial packet of `OP-state-storage` until current repository, reader, publication and lock bindings pass their combined verification. Root owns inventory and milestone reconciliation; helper paths create no extra operation credit. Native and broader project acceptance remain outstanding.
