# Multi-repo workspace removal boundary

The multi removal application owns the complete source-order loop, removed and
error arrays, force branches and catch boundaries. Fifteen required synchronous
semantic ports supply native observations and effects. Construction validates
callability without invoking effects. Workspace, entry and registration proof
values remain opaque and are passed back unchanged; the application never
interprets native deletion authority.

The native removeWorkspace facade retains branch validation, path resolution,
workspace ownership, unreachable-repository checks, workspace identity capture
and unified/multi dispatch. Its multi binding keeps strict scans, existsSync
observations, worktree matching, registration fencing, error relay and quarantine
helpers with their original arguments. RemoveResult is domain-owned and remains
public, synchronous and mutable through the original root export.

Source scan, destination calculation, initial existence, repository workspace
assertion, matching, unmanaged description and repository identity capture remain
outside per-entry catches. Registration capture completes before the strict
force read inside the repository try. Copy assertion, fresh scan, identity,
quarantine and successor existence observation remain inside the copy try.
Relay receives the original unknown thrown value; relay exceptions escape.

Final workspace existence and identity assertion remain inside the final try.
Identity assertion precedes the existing-error return. Empty workspaces are
quarantined; nonempty ones use a separate truthy force read and fresh scan that
refuses Git content before quarantine. Strict entry force and truthy final force
are deliberately distinct. Options retain their original object reference,
getter observations and catch placement. The final catch preserves direct
message-property access, including the original nullish-throw behavior.

Copied entries that become repositories or are recreated remain refused. Native
inode, ref, backpointer and quarantine checks retain authority; no branch ref is
deleted. In the normal facade, outer ownership validation already refuses an
unowned repository even with force, before the application's unmatched-worktree
branch can run. Moving this branch does not relax that policy.

Ordered core fault tests cover orchestration; facade and existing real-Git race
regressions cover native authority. Both actual shipping forms must execute the
compiled application and native create/remove with preserved source refs,
configuration and files. This internal parity refactor introduces no new REQ,
ADR or POLICY; existing destructive-operation requirements continue to apply.
Unified removal, repair, outer dispatch migration and native platform acceptance
remain separate work.
