# Unified workspace removal boundary

The unified removal application owns the complete nested-before-root removal
operation. Twenty-seven required synchronous ports supply observations and
native effects. Construction checks callability without executing effects.
Directory, source, destination, registration and quarantined-root proofs remain
opaque. Source proofs support object or symbol identity because the original
source map lookup tests truthiness; other proof types remain unrestricted.

The public removeWorkspace facade retains validation, ownership, unreachable
path handling, initial workspace identity capture and unified/multi dispatch.
Its unified binding retains Git commands, status exclusions, native registration
and inode checks, pinned source environments and quarantine rollback authority.
No branch refs are deleted. RemoveResult remains synchronous and mutable.

The application scans source entries, checks ordinary and ignored root status,
projects destination entries and captures every source identity before removing
nested worktrees in reverse order. The operation guard checks workspace, source
and destination in that order. Its initial invocation escapes the entry catch;
registration capture, native removal and the final guard share the entry catch.
Only recognized unreachable metadata errors are suppressed. Other metadata,
tracked-status and identity observation errors preserve their original catches.

Status observations defer diagnostic and content decoding to their original
use sites. A forced removal still performs ordinary and ignored status commands
and refuses observation failure, but skips content decoding where the original
force short circuit skipped it. Root branch observation reads stdout before its
failure predicate and retains a nonempty branch in diagnostics after failure.
Options retain the original object reference and force getter evaluation order.

After nested success, the application verifies root ownership and branch, then
rechecks ordinary and ignored status. Root registration capture precedes the
strict force read that selects the optional quarantined-content veto. The
native root removal helper always receives literal true; strict user force
removes only that content veto. Without force, late ordinary or ignored content
causes the existing native quarantine helper to restore the root safely.

Verify ordered core fault cases, opaque and readonly declaration contracts,
actual native late-content rollback, source/ref/config preservation and existing
worktree regressions. Both extracted npm and materialized install payloads must
execute the compiled application and native facade and compile emitted types.
Guarded CLI proof remains separate from package-module proof.

## Known ceiling

This is an internal parity extraction. Outer workspace dispatch and repair,
credential paths, final composition closure and native Windows/macOS acceptance
remain separate work. Passing pure or portable tests does not certify them.
