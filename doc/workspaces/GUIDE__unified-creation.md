# Unified workspace creation boundary

The unified creation application composes the shared worktree addition operation
with explicit registration, naming, nested repair and root compensation ports.
Native adapters retain Git commands, OID/config snapshots, registration proof,
inode identity and quarantine execution. Prepared and registration values remain
opaque references; application code must not inspect or fabricate them.

The successful trace is addition, registration requirement, source name, nested
repair and result assembly. Root creation appears first, followed by the existing
nested entry order; copied entries remain an empty mutable array. Domain owns
the unchanged public result/action shapes, with legacy facade type exports kept.

Only an exception from nested repair triggers root compensation. Registration,
naming and result-assembly exceptions propagate without new cleanup. Compensation
checks the root, removes its exact registered incarnation, then rolls back the
created branch. A failed check or removal stops later cleanup. Successful cleanup
rethrows the original repair value; failed cleanup preserves the old message,
array/join behavior and original cause without normalizing unknown thrown values.

Verify ordered core traces, every required port and constructor isolation,
opaque identity, error boundaries and throwing result iterators. Actual private-Git
facade tests and existing worktree regressions verify root/branch compensation,
replacement preservation and tracking restoration. Both shipping payloads must
exercise compiled policy, actual nested-Git creation and old mutable type exports.

Outer dispatch, multi-repo orchestration, nested repair internals and overall
removal remain subsequent migration work. This operation does not complete M11
or native Mac/Windows acceptance.
