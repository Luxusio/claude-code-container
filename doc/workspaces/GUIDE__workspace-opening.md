# Workspace opening

The CLI's `prepareWorktree` composes `createWorkspaceOpen`. The application owns existing-versus-new selection, confirmations, repair admission, semantic event reporting and final ownership/readiness validation and one damaged-metadata retry. Required finite ports retain native path and project identity, Git observations and mutations, owner checks, boolean confirmation purposes and the project-family critical scope. Creation and root, nested and content repair reuse their existing accepted peers; this adds no workspace feature.

The domain defines finite opened/refused outcomes and operation-specific events and confirmation purposes. The application contains no terminal strings, prompt decoding, console or process exit. `createWorkspaceOpenPresentation` owns the existing terminal bytes, exact `y`/`yes` confirmation decoding and recovery failure Error construction with a terminal-safe detail capped at 500 characters. The CLI renders a returned refusal and exits with status 1 after the family scope releases. Validation, submodule initialization and creation refusals terminate the attempt before any later mutation or final guard. Native owner and damaged-metadata exceptions retain their original identity.

Each opening attempt holds the project-family lock through ordinary confirmation prompts. When the source directory has Git metadata, existing workspaces first undergo native root ownership repair and assertion. Missing registration is diagnosed, then native registration preflight is captured before confirmation. The adapter preserves the optional captured fence, wrapping its synchronous return when present and passing it to recovery; it does not substitute a no-op fence when absent. Declining confirmation rethrows the original owner error. Failed recovery throws the native presenter’s bounded recovery error, while successful recovery reasserts ownership before continuing. Without source Git metadata, the existing-workspace path instead runs the native readiness guard with tracked Gitlinks disallowed before subsequent repair decisions.

After root qualification, a required native topology inspection runs before nested creation and content-repair prompts. It checks existing repositories without requiring absent new child checkouts to exist; final readiness checks complete source ownership. A foreign nested repository is refused before repair can replace its Git metadata. The native inspection uses existing readiness observations without a source-completeness check.

An existing @argument selects the workspace directory; healthy repositories retain their independent current branches, even when the root branch differs from the directory alias. Normal execution and --resume apply this same policy without switching branches or altering refs, indexes, files or registrations. Nested repair results are reported; broken content is repaired only after confirmation. New workspaces and missing empty child checkouts still use the requested branch. New-workspace opening retains optional submodule initialization and delegates creation to the accepted creation application. Both paths finish with the native readiness guard allowing tracked Gitlinks; application routing does not replace that guard's ownership or physical-path authority.

A damaged-metadata exception unwinds the family scope before the repair prompt and native Git registration repairs. No repair list, declined confirmation or all failed repair outcomes propagate the original error. If at least one repair succeeds, the application reacquires the same family scope for one new attempt. A second error propagates without another repair loop. Partial native repairs remain actual effects; this introduces no transaction or rollback promise.

Ordinary CLI/worktree tests and focused application/type cases cover decisions, required synchronous effects and native composition. Current review, strict compilation, genuine build, runtime/package checks and local delivery remain acceptance work. This Guide claims no executed QA, native certification, formal close or `OP-workspace-open` credit.
